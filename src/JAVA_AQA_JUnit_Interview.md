# Вопросы для собеседования Java AQA: JUnit 5

Материал ориентирован на подготовку Java QA Automation Engineer. Вопросы расположены примерно от базовых к более сложным. После каждого блока приведены темы, которые желательно раскрыть в ответе.

## 1. Основы JUnit

1. Что такое JUnit и для чего он используется?
2. Чем unit-тест отличается от интеграционного и end-to-end теста?
3. Из каких основных модулей состоит JUnit 5?
4. Чем JUnit 5 отличается от JUnit 4?
5. Что такое JUnit Platform, JUnit Jupiter и JUnit Vintage?
6. Как подключить JUnit 5 к Maven-проекту?
7. Как Maven находит и запускает тестовые классы?
8. Какие требования предъявляются к тестовому методу в JUnit 5?
9. Обязательно ли тестовый класс и тестовые методы должны быть `public`?
10. Почему тесты должны быть независимыми друг от друга?

Что важно упомянуть: `junit-jupiter`, аннотация `@Test`, Maven Surefire Plugin, соглашения об именовании тестов, повторяемость и изоляция тестов.

7. Для чего нужна аннотация `@DisplayName`?

## 10. Мини-задачи на чтение кода

### Задача 1. Найдите проблему

```java
class CalculatorTest {
    private static int result;

    @Test
    void firstTest() {
        result = 10;
        assertEquals(10, result);
    }

    @Test
    void secondTest() {
        assertEquals(0, result);
    }
}
```

Вопросы:

1. Почему `secondTest` может падать?
2. Как переписать тесты, чтобы они были независимыми?
3. Что изменится при параллельном запуске?

### Задача 2. Улучшите проверку исключения

```java
@Test
void shouldRejectNegativeAge() {
    try {
        userService.create("Alex", -1);
    } catch (IllegalArgumentException exception) {
        assertEquals("Age must be positive", exception.getMessage());
    }
}
```

Вопросы:

1. Почему этот тест может успешно пройти, даже если исключение не выброшено?
2. Перепишите его с использованием `assertThrows()`.

### Задача 3. Оцените мокирование

```java
@Mock
private User user;

@Test
void shouldReturnFullName() {
    when(user.getFirstName()).thenReturn("Alex");
    when(user.getLastName()).thenReturn("Ivanov");

    assertEquals("Alex Ivanov", user.getFirstName() + " " + user.getLastName());
}
```

Вопросы:

1. Что на самом деле проверяет этот тест?
2. Почему здесь mock не нужен?
3. Какой реальный production-метод стоило бы тестировать?

# Задания для закрепления материала

## Задание 1. Базовые unit-тесты

Создайте класс `Calculator` с методами:

```java
int add(int a, int b)
int subtract(int a, int b)
int multiply(int a, int b)
double divide(int a, int b)
```

Напишите тесты, которые проверяют:

- обычные положительные и отрицательные значения;
- ноль;
- деление с дробным результатом;
- деление на ноль и свойства выброшенного исключения;
- несколько независимых проверок через `assertAll()`.

## Задание 2. Параметризованные тесты

Создайте метод `boolean isPalindrome(String value)` и проверьте его через `@ParameterizedTest`.

Требования:

- используйте `@ValueSource` для корректных палиндромов;
- используйте `@NullSource` и `@EmptySource` для граничных случаев;
- через `@CsvSource` передайте строку и ожидаемый результат;
- отдельно определите ожидаемое поведение для регистра, пробелов и знаков препинания.

## Задание 3. Валидация пользователя

Реализуйте `UserValidator`, который проверяет имя, email и возраст пользователя.

Напишите тесты для:

- корректного пользователя;
- пустого и `null` имени;
- некорректного email;
- возраста `-1`, `0`, `17`, `18` и максимально допустимого значения;
- проверки типа и сообщения исключения;
- группировки сценариев с помощью `@Nested` и `@DisplayName`.

## Задание 4. Тестирование сервиса с Mockito

Создайте `UserService`, зависящий от `UserRepository` и `EmailSender`. Метод регистрации должен сохранить пользователя и отправить приветственное письмо.

Проверьте, что:

- при корректных данных вызываются `repository.save()` и `emailSender.send()`;
- при существующем email выбрасывается исключение;
- при ошибке валидации репозиторий и отправщик писем не вызываются;
- аргумент, переданный в репозиторий, имеет ожидаемые поля;
- лишних обращений к зависимостям нет.

Используйте `@ExtendWith(MockitoExtension.class)`, `@Mock`, `@InjectMocks`, `verify()`, `never()` и `ArgumentCaptor`.

## Задание 5. Устранение нестабильности

Дан тест, который использует `LocalDateTime.now()`, случайный UUID и `Thread.sleep()`.

Переработайте production-код и тест:

- внедрите `Clock` вместо прямого обращения к текущему времени;
- внедрите интерфейс генератора идентификаторов;
- замените ожидание фиксированной длительности на контролируемое условие;
- добейтесь одинакового результата при многократном и параллельном запуске.

## Задание 6. Собственный JUnit Extension

Создайте extension, который измеряет продолжительность каждого теста и выводит имя теста вместе со временем выполнения.

Дополнительно:

- реализуйте интерфейсы `BeforeTestExecutionCallback` и `AfterTestExecutionCallback`;
- храните начальное время в `ExtensionContext.Store`;
- подключите extension через `@ExtendWith`;
- добавьте проверку или предупреждение для тестов, выполняющихся дольше заданного порога.

## Задание 7. Рефакторинг плохого тестового набора

Найдите или создайте набор тестов со следующими проблемами:

- тесты зависят от порядка выполнения;
- используется общее изменяемое статическое состояние;
- присутствуют `Thread.sleep()` и случайные данные без фиксированного seed;
- один тест проверяет несколько несвязанных сценариев;
- названия тестов не описывают ожидаемое поведение;
- все зависимости замокированы, включая простые DTO.

Перепишите набор и кратко объясните каждое изменение.
